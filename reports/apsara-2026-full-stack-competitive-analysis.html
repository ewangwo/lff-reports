0 管理层摘要

核心判断：阿里正在把“模型生产、Agent运行、企业数据”连接为一套云服务体系，并将这种体系向下延伸至自研芯片、互联、服务器和存储。对华为而言，竞争已经同时发生在器件、系统架构、软件平台与客户业务入口；阿里作为客户的基础设施需求仍可能增长，但外部供应商可参与的部分需要逐层判断。

核心判断 主要证据 竞争与客户需求含义 判断把握
1. 真武已有云交付基础，V900是下一代路线 GP9A正式规格、ACK部署文档；V900计划2027Q1 当前比较M890可用服务，未来比较V900；不要把路线图当现货 高，交付数量未知
2. CPU、网络、存储重新成为Agent关键路径 倚天双路线、ICN、HPN、CPFS及沙箱 仅以AI卡性能理解客户需求将漏掉通算与数据系统 高，具体采购量未知
3. 芯片竞争正转为系统与软件竞争 真武—ICN—磐久—SAIL；昇腾—灵衢—超节点—CANN 有效产出、迁移成本和运维效率比孤立参数更接近客户决策 中高，缺同条件测试
4. 两家的Agent基础设施方向趋同 阿里Agent Native Cloud；华为Agentic Infra、AgentArts及记忆存储 不能把华为仅看成硬件方，也不能把阿里仅看成云服务方 高，平台强弱仍待实测
5. 阿里将数据与Agent运行一起产品化 Agent Context、OpenLake、AgentCore、Agent Sandbox 客户依赖可能从模型API延伸到身份、状态、数据与运行环境 中高，黏性为分析
6. 开放生态与自研控制同时增强 SAIL、开源模型、Kubernetes/E2B兼容；自研芯片与互联 软件开放不等于采购开放；参与边界取决于接口和架构 高，采购边界未披露
7. 全球化扩张增加部署复杂性 9月23日新增地域规划及国际AI产品 海外部署、网络与服务交付是独立需求维度 高，新增容量及供应商未知
8. 2027年是新一轮产品兑现窗口 V900与960DT计划2027Q1；倚天720/730、960PR在2027年后续节点 比较需要按实际可交付月份更新，不能用2025旧路线图固定结论 高，计划可能变化

上述判断主要对应用户原图30—49及[A01][A02][A03][A04][H01][H02][H05]。目前证据不足以判定V900与960的综合性能胜负，也不足以确认阿里对华为的采购份额或供货关系已发生变化。

1.2 必须修正的历史理解

M890、AL128、SAIL并非9月才首次出现：5月公告已有芯片和系统信息，7月WAIC已有SAIL开源披露。[A06][A07] AgentCore计费开始时间早于大会；Alibaba Cloud Linux 4也在会前已有4.0.6版本。[A10][A11] 因而，本次的新增价值主要在于后续代际、系统集成及Agent产品组合，不能把全部在台上出现的产品都计入“本届新产品”。

官方弹性计算议程同时写到第十代实例发布和g9i/g9ae案例；本报告不把后两者直接改名为第十代。产品目录、演示案例和真正新规格仍需分别核对。[A16]

分析示意：按职责分层，实际调用和数据流并非严格串行。

阿里在官方发布中用Model、Harness、Context组织Agentic Cloud。可分别理解为：模型负责生成与推理；运行与治理层负责把推理变成可靠执行；数据与记忆层负责让任务拥有业务上下文。[A01]

业务与技术关系：企业/终端任务 → Qwen及多模型服务 → Agent运行与治理 → Context与数据平台 → 计算、网络和存储 → 真武/倚天/互联芯片与数据中心。

这是一张按职责组织的阅读图，实际数据流包含多方向调用，不能理解为严格串行执行。

【分析】这一组合的竞争含义，是阿里希望同时掌握任务入口、执行平台及底层资源。 模型可以带来开发者，平台把模型变成可用服务，资源使用又为底层芯片和基础设施提供优化反馈。如果这些环节能共享工作负载信息，阿里可以围绕自身模型和业务持续优化系统；代价则是需要同时承担更多层研发、运营与兼容责任。

华为同期发布围绕昇腾、鲲鹏、灵衢和记忆存储组织AI基础设施，华为云又提供MaaS和企业Agent平台。[H03][H05] 两者的业务重心有差异，但产品覆盖存在明显交集，不能简化为“阿里做应用、华为做硬件”。

系统组织 自研芯片与自营云产品结合 芯片、互联、整机、伙伴及云服务 比较应同时考虑供给方式和客户使用方式

3 模型与Agent：计算需求从一次回答变成持续任务

3.1 能力上限与单位使用效率同时推进

原图显示Qwen3.8-Max采用2.4T总参数、95B激活参数，Flash/Plus/27B侧重效率。MoE总参数大并不意味着每个Token都计算全部参数，但模型权重存储和专家调度仍占用资源。图10的激活参数1/3、训练FLOPs1/9、输入价格1/4、1M预填充吞吐8.6倍，分母和任务不同，不能相乘得出统一的成本改善。

Qwen4处于训练阶段；图像3.1的正式发布时间被官方稿限定在今年晚些时候。对外展示能力、可调用API和广泛商用应分别记录。[A01] 音频与同传产品增加实时性要求，世界模型的持续交互则增加状态与记忆压力。本文没有对模型排行榜、胜率和跨厂商质量作独立测评。

3.3 自我改进：实验进展与通用能力分开

原图46把完整RSI作为后续方向；新取得的官方稿则披露了模型自动迭代实验。因此，应更新为“已有受控实验进展，通用自主持续进化能力及平台商用仍未证实”，而不是笼统写“完全没有实现”。[A01] 原图08的EDA案例对象是总线模块，面积改善不等于整颗芯片成本下降，也不能证明工程师或EDA工具被替代。

【分析】产品与解决方案层面的结论：每次任务可能交替使用模型推理、CPU工具、数据访问与再次推理，资源需求呈混合和脉冲特征。增加加速卡不是所有瓶颈的解法。

3.4 模型竞争与模型适配是不同关系

阿里拥有自有Qwen模型及云服务入口，华为官方同时强调盘古、第三方模型与多模型算力生态。[A01][H01][H05] 因此，不能把模型层简化为Qwen与盘古的单一榜单比较：还应看模型是否开放、能在哪些硬件部署、通过谁的MaaS收费，以及企业应用绑定哪套平台。

【分析】Qwen生态扩大会提高其模型服务的竞争力，也可能增加其他兼容基础设施上的部署需求；两种结果可以并存。具体是否形成华为算力需求，取决于对应版本许可证、模型适配、性能及客户部署选择。本轮未取得Qwen与盘古在同一任务、成本、时延和质量条件下的完整测试，不输出基础模型质量排名。

4.2 M890的产品化意味着什么

GP9A官网列明M890P、64卡/8节点最小售卖单元、每卡144GB显存；合计9216GB显存与18.4TB主机内存是不同资源，不能相加成等效显存。地域列明乌兰察布，中卫仍为规划。[A03] ACK文档给出设备插件、拓扑感知调度和ICN域检查流程。[A04]

6.4 系统效率比卡数更接近价值

7.2 HPN的重要口径修正

8 存储与数据基础设施：训练供给、推理缓存和Agent状态分开

8.1 CPFS首先解决训练数据供给

原图45宣称CPFS容量5倍、性能10倍、TCO下降69%；官方稿补充百TB/s级吞吐和亿级IOPS方向。[A01] 这些属于厂商发布，缺少旧版本规格、读写比例、文件大小、客户端规模、元数据压力和计价基础，不作为所有工作负载的统一收益。

【分析】CPFS的价值不只在峰值带宽：读取训练数据、加载权重、写入Checkpoint、故障后恢复都可能影响加速卡有效工作时间。若存储更快但网络或数据预处理仍堵塞，整体训练增益可能明显低于存储层增益。因此，华为对应AI训练存储应按完整数据路径对比，不能拿单设备带宽与云服务聚合带宽比较。

8.2 三类“记忆”不能混为一谈

数据类型 典型内容 主要要求 对应比较对象

8.3 阿里KVCacheStore与华为M900：功能交集较清晰

阿里官方文档将KVCacheStore定位于推理缓存存储，提供KV接口、亲和算力部署、独立扩容与灵骏裸金属挂载；列有单客户端40GB/s、系统最高100PiB等规格。[A23] 这些是规格上限，不能相乘后声称生产性能。

华为M900面向超节点提供PB级共享KV空间，借助灵衢连接与分层缓存调度；其产品价值也围绕减少推理重复计算和扩大上下文承载。[H04] 双方竞争交集成立，但产品层次并不完全相同：阿里提供云上缓存存储服务及软件管理，华为同时披露记忆存储系统与互联协同。

Tair KVCache Manager在官方开源仓库中承担元数据管理、缓存查询与容量管理，并由连接器对接推理引擎。[A13] 它不能被直接等同为整套存储设备，软件开源也不能证明硬件后端可任意无代价替换。

8.4 对华为存储比较的实际含义

应按“数据准备→训练读取→Checkpoint→推理缓存→Agent状态”分别比较。评价指标包括成功训练时间、首Token延迟、缓存复用、数据新鲜度和有效容量成本；TCO还应考虑重复拷贝、缓存空间、闪存耐久与网络。当前资料不足以对OceanStor各系列与阿里各服务给出统一性能排名。

9 数据库与数据平台：价值从保存数据向提供可用上下文延伸

9.1 已确认的增量

Agent Context把实时上下文与长期记忆作为服务对象；OpenLake强调多种数据形态与多引擎共用数据底座。[A01] 两者分工不同：前者靠近Agent“取什么上下文”，后者靠近数据如何存放、治理和处理。

【分析】如果企业把权限、数据更新、检索与Agent执行连接起来，迁移成本不只来自模型API。数据管道、身份关系、查询方式和任务记忆也需要重建。因此，数据库竞争正在同时发生在数据引擎效率与Agent数据服务层。

【分析】安全需要从用户身份扩展到Agent身份、工具授权、代码执行和审计。VM隔离能控制部分执行风险，不能单独保证Agent业务决策正确；控制平面、数据权限和工具连接共同决定企业可接受的运行边界。

12.3 哪些证据会改变结论

V900绝对算力、功耗和HBM带宽的正式规格，会改变芯片判断；相同模型与质量门槛的测试，会改变系统效率判断；地域库存和持续运行资料，会改变交付成熟度判断；标准接口和第三方认证，会改变外部参与边界判断。产品级收入、续用与真实合同材料，才可能改变商业化深度判断。

13 阿里作为客户：需求增长与外部份额是两件事

13.1 产品需求影响矩阵

发布/架构变化 可合理推导的需求方向 涉及产品 自研带来的限制 尚不能确认
大模型与Agentic RL 加速计算、通算环境、存储和调度协同 AI算力、CPU、网络、存储 真武/倚天承接更多内部需求的可能性 外采比例、项目规模
新磐久与ICN域扩大 高密供电冷却、互联和运维 机柜、光电部件、DC设施 核心协议与关键芯片控制增强 第三方接入及BOM

表中需求方向属于技术分析，不等同阿里已提出的采购要求。自研覆盖增加可能压缩某些成套产品的替代空间，也可能增加配套器件、连接和工程需求；没有架构与采购资料，就不能把其中任一方向写成确定订单机会。

13.2 三种开放必须分开

模型/软件开放回答开发者能否使用；协议/接口开放回答系统能否互通；采购开放回答谁有资格供货。SAIL开源不自动证明ICN互通，模型可在昇腾运行也不自动证明阿里采购昇腾。技术层面的交集与商业关系不能互相代替。

综合判断：阿里正在由多类设备和服务的使用者，进一步成为算力架构与Agent运行体系的定义者。华为产品与阿里的关系需要逐层评估：在某些层直接竞争，在某些层存在技术适配交集，在另一些层仍缺少采购边界证据。

Scale-out 将节点/超节点组成更大集群，强调网络与分布式扩展
MFU 模型实际计算对理论峰值算力的利用程度，必须结合模型和计算口径
TTFT / TPOT 首Token时间 / 后续每Token时间，不能互相替代
KV Cache 注意力计算的中间缓存，与Agent长期业务记忆不同
Harness 让模型执行任务的工具、状态、流程、权限和评测运行体系
Context 执行当前任务所需的信息、历史与业务数据
NPO 光引擎靠近芯片封装的光互联形态，不等于所有光互联技术
GA / Preview 正式可用 / 预览，均须核对地域、版本和服务条款
