# IBKR 持仓估值与风险雷达设计

## 目标

在 `ewangwo/lff-reports` 中发布一个公开代码、私有数据的投资监控网页。页面刷新时读取最新互联网数据快照，展示长期趋势、两年价格与估值分位、成交量、情绪、SEC 财报与股权事件，并在“低于 200 日均线”与“价格及 TTM PE 均低于两年 10% 分位”同时成立时生成只读人工复核提醒。

## 隐私和安全边界

- GitHub 仓库是公开的，仓库中不得出现账户号、持仓数量、成本、净资产、盈亏、订单或 API 密钥。
- 第一阶段只发布公开市场研究数据和演示股票池；私人持仓由后续受保护接口或本机加密桥接提供。
- TWS 保持 Read-Only API；网页和采集脚本均不得包含下单、改单或撤单调用。
- 页面必须显示数据来源、数据日期、新鲜度和缺失状态；旧数据不得标记为实时。
- 信号只写“人工复核”，不输出买入、卖出或抄底建议。

## 第一阶段架构

1. `radar-app/`：React、TypeScript、Vite 源码。
2. `scripts/radar_data/`：Python 数据采集与指标计算。
3. `data/ibkr-radar/public-snapshot.json`：GitHub Actions 生成的公开安全快照。
4. `tools/ibkr-radar/`：Vite 构建产物，由 GitHub Pages 直接托管。
5. `.github/workflows/update-ibkr-radar.yml`：定时刷新公开行情和 SEC 事件，构建并提交静态快照。

网页每次加载都使用 `cache: no-store` 请求快照并附加时间戳参数，确保获得 GitHub Pages 上的最新版本。GitHub Actions 的最短定时粒度和外部源限流决定数据不是逐秒实时；页面必须显示快照生成时间。

## 数据与计算口径

- 两年日线：优先使用 Yahoo Chart JSON 作为公开行情源；失败时保留上次成功快照并标记过期。
- SEC：使用 `data.sec.gov/submissions` 和 `companyfacts`，并遵守 User-Agent 要求。
- `SMA200`：最近 200 个有效完整交易日的调整收盘价均值。
- 两年价格分位：当前完整交易日收盘价在最多 504 个有效日线观测中的经验百分位。
- 相对成交量：当前完整交易日成交量除以前 20 个完整交易日平均成交量。
- TTM PE：价格除以截至该日已公开的最近四个季度稀释 EPS。无法无前视偏差重建时显示“数据不足”，不生成估值信号。
- PE 百分位：当前正 TTM PE 在过去两年有效正 PE 序列中的经验百分位。
- ETF：不使用公司 PE；显示 `N/M` 和证券类型说明。

## 信号

- A：最新完整交易日收盘价低于 SMA200。
- B：两年价格分位不高于 10%，且两年 TTM PE 分位不高于 10%，样本充分。
- C：A 与 B 同时成立，状态为“人工复核”。
- A 或 B 单独成立时只显示“观察”。

## 页面

- 顶栏：产品名、公开数据模式、快照时间、持仓/提醒/数据健康导航。
- 摘要栏：覆盖证券数、A/B/C 数量、过期或缺失数据数量。
- 主表：Ticker、价格、SMA200、偏离、价格分位、TTM PE、PE 分位、相对成交量、事件、状态。
- 事件栏：SEC 财报、8-K/6-K、Form 4、13D/13G 等最新事件。
- 个股详情：两年价格/SMA200、成交量、PE 分位、数据来源和解释。
- 数据健康：每个来源的更新时间、状态和错误。

## 第二阶段

第二阶段在获得受保护云后端或加密密钥设施后接入私人持仓。公开仓库仅保留接口契约；私人快照不得进入 Git 历史。TWS 离线时显示最后快照时间，不进行实时性推断。

## 验收

- 指标单元测试覆盖 SMA200、百分位、负 EPS、ETF、样本不足和 A/B/C 组合。
- 数据采集失败不破坏已有快照。
- React 测试验证筛选、选中详情、刷新状态和数据健康。
- `npm test`、`npm run build`、Python 测试通过。
- 构建产物不含账户号、真实持仓数量、成本、盈亏或密钥。
- GitHub Pages URL 可打开，页面显示明确的公开数据模式与时间戳。
